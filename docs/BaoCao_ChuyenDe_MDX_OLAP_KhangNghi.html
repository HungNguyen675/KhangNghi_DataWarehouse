PHẦN I: TỔNG QUAN VỀ NGÔN NGỮ TRUY VẤN ĐA CHIỀU MDX

1.1. Khái Niệm & Vị Trí Trong Kiến Trúc BI

MDX (Multidimensional Expressions) là ngôn ngữ truy vấn tiêu chuẩn được phát triển bởi Microsoft vào năm 1997 (xuất hiện lần đầu trong chuẩn OLE DB for OLAP và tích hợp sâu trong SQL Server Analysis Services - SSAS). Về sau, MDX trở thành chuẩn công nghiệp thực tế (de-facto standard) cho các hệ quản trị khối đa chiều OLAP.

Trong kiến trúc BI của Công ty Khang Nghị, MDX nằm ở tầng kết nối phân tích giữa khối MOLAP (`KhangNghi_Cube`) và các ứng dụng tiêu thụ dữ liệu (Web Dashboard SPA, Power BI):

  • Dữ liệu nguồn (Excel/ERP) → ETL (SSIS) → Kho dữ liệu (DWH_KhangNghi).
  • Kho dữ liệu → Khối đa chiều SSAS MOLAP (KhangNghi_Cube) → Engine truy vấn MDX.
  • MDX Engine → ASP.NET Core Web API (SsasController) → Web Dashboard trực quan & Power BI.

1.2. Các Khái Niệm Toán Học & Cấu Trúc Không Gian Trong MDX

Khác biệt căn bản giữa SQL và MDX nằm ở không gian biểu diễn dữ liệu:

  • Cube (Khối lập phương đa chiều): Không gian $N$ chiều lưu trữ các độ đo và trục ngữ cảnh. Trong đồ án là [KhangNghi_Cube].
  • Measures (Độ đo định lượng): Các chỉ tiêu tính toán số học được gom nhóm theo Measure Groups ([Measures].[Sales Amount], [Measures].[Profit Amount], [Measures].[Quantity On Hand],...).
  • Dimensions (Chiều phân tích) & Hierarchies (Cây phân cấp): Trục ngữ cảnh phân loại dữ liệu theo quan hệ cha - con:
    • Thời gian: Year → Quarter → Month → Day → Full Date.
    • Sản phẩm: Category → Sub Category → Product Name.
    • Địa lý: Region → Country → State → City.
  • Member (Phần tử): Một giá trị cụ thể trong một chiều phân cấp (ví dụ: [Dim Time].[Year].&[2026]).
  • Tuple (Bộ tọa độ): Giao điểm của các phần tử thuộc các chiều khác nhau, xác định chính xác một ô giá trị (Cell) trong không gian n chiều. Ký hiệu bằng ngoặc đơn (...). Ví dụ: ([Dim Time].[Year].&[2026], [Dim Location].[Region].&[Miền Nam], [Measures].[Sales Amount]).
  • Set (Tập hợp): Tập gồm 0 hoặc nhiều Tuple cùng cấu trúc chiều, ký hiệu bằng ngoặc nhọn {...}. Ví dụ: {[Dim Time].[Year].&[2025], [Dim Time].[Year].&[2026]}.

1.3. Bảng Ma Trận So Sánh Toàn Diện Giữa MDX và SQL

Tiêu chí SQL (Structured Query Language) MDX (Multidimensional Expressions)
Mô hình dữ liệu CSDL quan hệ (RDBMS) - Bảng 2 chiều phẳng gồm các Dòng và Cột độc lập. Khối lập phương đa chiều (Hypercube) gồm Measures, Dimensions và Hierarchies.
Hệ trục kết quả Chỉ trả về duy nhất 1 tập bảng phẳng 2 chiều. Hỗ trợ đa trục độc lập: COLUMNS (Axis 0), ROWS (Axis 1), PAGES (Axis 2),...
Cơ chế tổng hợp Thực hiện quét dòng, JOIN, SUM, GROUP BY tại thời điểm chạy. Dữ liệu tổng hợp (Aggregations) đã được tiền tính toán sẵn trong khối MOLAP.
Hiệu năng Chậm rõ rệt khi bảng Fact có hàng triệu dòng và nhiều phép JOIN phức tạp. Phản hồi tức thời (< 0.5s) nhờ cấu trúc lưu trữ nén và bộ đệm cache SSAS.
Điều hướng phân cấp Rất phức tạp, phải viết các truy vấn đệ quy CTE (WITH RECURSIVE). Hỗ trợ tự nhiên qua các hàm có sẵn: .CHILDREN, .PARENT, DESCENDANTS().
Phân tích chuỗi thời gian Phức tạp, đòi hỏi các hàm Window Functions (LAG, LEAD, OVER). Cực kỳ mạnh mẽ với các hàm chuyên dụng: PARALLELPERIOD(), YTD(), QTD().

PHẦN II: HIỆN THỰC HÓA 4 THAO TÁC OLAP CỐT LÕI BẰNG MDX

2.1. Thao Tác ROLL-UP (Cuộn Gộp / Tổng Hợp Hóa)

Khái niệm: Di chuyển từ mức độ chi tiết cao (hạt mịn - fine grain) lên mức độ tổng quát hơn (hạt thô - coarse grain) theo chiều phân cấp. Thao tác này tương đương với việc cuộn gộp dữ liệu từ Ngày → Tháng → Năm. 

-- TRƯỚC KHI ROLL-UP: Xem chi tiết theo từng ngày lẻ (Full Date)
SELECT 
    [Measures].[Sales Amount] ON COLUMNS,
    [Dim Time].[Full Date].MEMBERS ON ROWS
FROM [KhangNghi_Cube];

-- SAU KHI ROLL-UP: Cuộn gộp lên cấp Năm (Year)
SELECT 
    [Measures].[Sales Amount] ON COLUMNS,
    [Dim Time].[Year].MEMBERS ON ROWS
FROM [KhangNghi_Cube];

2.2. Thao Tác DRILL-DOWN (Khoan Sâu / Chi Tiết Hóa)

Khái niệm: Thao tác đảo ngược của Roll-up, đi từ cấp tổng quan xuống sâu các tầng bên dưới của cây phân cấp nhằm truy vết nguyên nhân (Root Cause Analysis). 

-- Kỹ thuật: Dùng hàm DESCENDANTS khoan từ Category xuống chi tiết từng Product
SELECT 
    { [Measures].[Sales Amount], [Measures].[Profit Amount] } ON COLUMNS,
    DESCENDANTS(
        [Dim Product].[Category].&[Nội thất văn phòng],
        [Dim Product].[Product Name]
    ) ON ROWS
FROM [KhangNghi_Cube];

2.3. Thao Tác SLICE (Cắt Lát) & DICE (Chia Khối Đa Chiều)

A. SLICE: Cố định duy nhất 1 chiều tại một giá trị xác định thông qua mệnh đề WHERE (Slicer Axis), chiếu khối 3D thành 1 mặt phẳng 2D. 

-- SLICE: Cố định lát cắt CHỈ XEM KHU VỰC "Miền Nam"
SELECT 
    [Measures].[Sales Amount] ON COLUMNS,
    [Dim Product].[Category].MEMBERS ON ROWS
FROM [KhangNghi_Cube]
WHERE ([Dim Location].[Region].&[Miền Nam]);

B. DICE: Thu hẹp phạm vi khối dữ liệu thỏa mãn đồng thời nhiều tiêu chí lọc trên các chiều khác nhau (tạo ra Subcube con). 

-- DICE: Lọc đồng thời 2 chiều (Khu vực "Miền Nam" VÀ "Năm 2026")
SELECT 
    { [Measures].[Sales Amount], [Measures].[Profit Amount] } ON COLUMNS,
    [Dim Product].[Category].MEMBERS ON ROWS
FROM [KhangNghi_Cube]
WHERE (
    [Dim Location].[Region].&[Miền Nam], 
    [Dim Time].[Year].&[2026]
);

2.4. Thao Tác PIVOT (Xoay Chiều / Đổi Trục Góc Nhìn)

Khái niệm: Hoán đổi vị trí giữa các trục tọa độ (chuyển một Dimension từ Cột sang Hàng hoặc ngược lại) để đối chiếu trực quan ma trận chéo. 

-- PIVOT: Cột là Danh mục sản phẩm (Category), Hàng là Vùng miền (Region)
SELECT 
    [Dim Product].[Category].MEMBERS ON COLUMNS,
    [Dim Location].[Region].MEMBERS ON ROWS
FROM [KhangNghi_Cube]
WHERE ([Measures].[Sales Amount]);

PHẦN III: BÁO CÁO TỔNG KẾT CÔNG VIỆC, KHÓ KHĂN & GIẢI PHÁP

3.1. Phân Công & Trách Nhiệm Đảm Nhận

Trong khuôn khổ đồ án Khóa Luận Tốt Nghiệp, phân hệ SSAS OLAP & MDX đảm nhận trách nhiệm xây dựng lớp xử lý trung gian đa chiều, liên kết giữa Kho dữ liệu quan hệ (`DWH_KhangNghi`) với hệ thống Web Application SPA và Dashboard Power BI.

3.2. Những Kết Quả Đã Đạt Được

  1. Xây dựng thành công Khối Đa Chiều `[KhangNghi_Cube]`: Tích hợp mô hình Constellation Schema với 4 Fact cốt lõi (`Fact Sales`, `Fact Purchase`, `Fact Inventory`, `Fact Shipping`) và 13 Dimensions.
  2. Xây dựng bộ thư viện 40 câu truy vấn MDX mẫu: Phân loại rõ ràng 29 câu đã kiểm chứng thành công và 11 câu mẫu thiết kế chờ nạp đủ dữ liệu nguồn.
  3. Hiện thực hóa trọn vẹn 4 thao tác OLAP: Minh chứng đầy đủ Roll-up, Drill-down, Slice, Dice và Pivot với dữ liệu thực tế.
  4. Xây dựng các Calculated Measures động: Định nghĩa chỉ số tỷ suất lợi nhuận (Profit Margin %), cảnh báo thiếu hụt kho (Stock Deficit), đơn giá bình quân bằng cú pháp WITH MEMBER.
  5. Tích hợp hoàn chỉnh vào Web Backend ASP.NET Core: Viết mã nguồn SsasRepository.cs kết nối SSAS qua OleDb Provider MSOLAP.8, mở API POST /api/v1/ssas/query phục vụ giao diện Web.

3.3. Những Khó Khăn & Thách Thức Gặp Phải

  • Khó khăn 1 (Rào cản tư duy): Khác với tư duy bảng 2 chiều của SQL, việc chuyển sang tư duy không gian đa chiều (Tuples, Sets, Slicer Axis) ban đầu gây nhầm lẫn cú pháp cặp ngoặc () và {}.
  • Khó khăn 2 (Dữ liệu thưa - Data Sparsity): Do Cube có 13 Dimensions, các phép truy vấn chéo ban đầu trả về hàng ngàn dòng rỗng (NULL), làm phình to kích thước dữ liệu truyền về Web.
  • Khó khăn 3 (Kết nối Driver .NET Core): .NET Core không hỗ trợ tự nhiên thư viện ADOMD.NET cũ của .NET Framework; gặp vấn đề xác thực tài khoản Windows (SSPI) khi chạy Web API cục bộ.
  • Khó khăn 4 (Dữ liệu nguồn không đồng đều): File Excel thô của doanh nghiệp chủ yếu chứa dữ liệu Bán hàng. Dữ liệu phân hệ Mua hàng và Tồn kho không có sẵn trong file Excel nguồn ban đầu, dẫn đến chưa thể đối soát đúng sai thực tế cho 11 câu truy vấn này.
  • Khó khăn 5 (Tối ưu hiệu năng): Một số câu truy vấn MDX phức tạp sử dụng hàm FILTER() hoặc CROSSJOIN() ban đầu thực thi chậm do chưa tận dụng được bộ đệm Block Computation của SSAS.

3.4. Giải Pháp Khắc Phục & Bài Học Kinh Nghiệm

Thách thức Giải pháp thực tế đã triển khai Kết quả đạt được
Tư duy cú pháp MDX Vẽ sơ đồ hình học không gian tọa độ; viết đối chiếu câu lệnh tương đương giữa SQL và MDX; thử nghiệm từng hàm cơ bản trên SSMS. Làm chủ ngôn ngữ MDX, viết câu lệnh chuẩn xác, tối ưu.
Dữ liệu thưa (NULLs) Ứng dụng triệt để từ khóa NON EMPTY trước các trục COLUMNS và ROWS trong toàn bộ 40 câu truy vấn. Loại bỏ 100% dòng rỗng vô nghĩa, giảm 70% dung lượng payload JSON truyền về Web.
Kết nối Backend .NET Sử dụng System.Data.OleDb với provider MSOLAP.8 ổn định trên Windows; viết thuật toán tự động đọc Metadata bóc tách JSON. Kết nối ổn định, tốc độ phản hồi API trung bình dưới 0.3 giây.
Thiếu dữ liệu Mua & Tồn kho Phân định rõ ràng trong báo cáo: 29 câu đã kiểm chứng thực tế, 11 câu thiết kế mẫu theo Schema; xây dựng kịch bản Staging Script để chuẩn bị nạp dữ liệu. Bảo đảm tính trung thực khoa học trong báo cáo khóa luận trước Hội đồng.
Tối ưu hiệu năng Ưu tiên sử dụng TOPCOUNT() và BOTTOMCOUNT(); hạn chế Filter trên Member Sets quá lớn; thiết kế Aggregations hợp lý trong Cube. Truy vấn tối ưu, tận dụng tối đa bộ nhớ đệm cache của SSAS.

Mục 1: Phân Hệ Bán Hàng & Doanh Thu (Câu 01 - 10)

Trạng thái Mục 1: 10/10 câu đã thực hiện truy vấn thành công trực tiếp trên khối SSAS KhangNghi_Cube và API nhờ có sẵn đầy đủ dữ liệu thực tế từ bảng Fact_Sales.
Câu 01: Tổng Doanh thu, Lợi nhuận và Số lượng bán theo từng Năm (Roll-up) ĐÃ TRUY VẤN THÀNH CÔNG
Nghiệp vụ: Báo cáo tăng trưởng dài hạn cấp quản trị cao nhất, cuộn gộp dữ liệu từ ngày/tháng lên mức năm.
SELECT 
    { [Measures].[Sales Amount], [Measures].[Profit Amount], [Measures].[Quantity] } ON COLUMNS,
    [Dim Time].[Year].MEMBERS ON ROWS
FROM [KhangNghi_Cube];
Câu 02: Doanh thu theo từng Quý của một Năm cụ thể (Drill-down xuống Quý) ĐÃ TRUY VẤN THÀNH CÔNG
Nghiệp vụ: Theo dõi tiến độ hoàn thành chỉ tiêu kinh doanh theo từng quý trong năm tài chính 2026.
SELECT 
    { [Measures].[Sales Amount], [Measures].[Profit Amount] } ON COLUMNS,
    [Dim Time].[Year].&[2026].CHILDREN ON ROWS
FROM [KhangNghi_Cube];
Câu 03: Doanh số bán hàng chi tiết theo từng Tháng trong năm (Phân tích mùa vụ) ĐÃ TRUY VẤN THÀNH CÔNG
Nghiệp vụ: Đánh giá xu hướng chu kỳ tiêu thụ hàng hóa qua 12 tháng để chủ động nhập hàng.
SELECT 
    [Measures].[Sales Amount] ON COLUMNS,
    [Dim Time].[Month].MEMBERS ON ROWS
FROM [KhangNghi_Cube];
Câu 04: Doanh thu và Lợi nhuận theo Danh mục sản phẩm (Category) ĐÃ TRUY VẤN THÀNH CÔNG
Nghiệp vụ: Xác định ngành hàng mũi nhọn (Nội thất văn phòng, gia đình...) đóng góp vào dòng tiền.
SELECT 
    { [Measures].[Sales Amount], [Measures].[Profit Amount] } ON COLUMNS,
    [Dim Product].[Category].MEMBERS ON ROWS
FROM [KhangNghi_Cube];
Câu 05: Khoan sâu (Drill-down) từ Danh mục xuống Phân nhóm sản phẩm (Sub Category) ĐÃ TRUY VẤN THÀNH CÔNG

PHẦN V: TÍCH HỢP HỆ THỐNG VÀ THỰC THI TRÊN ASP.NET CORE API

5.1. Mã Nguồn Lớp Kết Nối SsasRepository.cs (.NET Core)

Trong mã nguồn dự án tại KhangNghi.Infrastructure/Repositories/SsasRepository.cs, việc kết nối tới SSAS được thực hiện thông qua nhà cung cấp OLE DB Provider (Provider=MSOLAP): 

using System;
using System.Collections.Generic;
using System.Data.OleDb;
using System.Threading.Tasks;

public class SsasRepository : ISsasRepository
{
    private readonly string _ssasConnectionString = 
        "Provider=MSOLAP;Data Source=localhost;Initial Catalog=KhangNghi_SSAS;Integrated Security=SSPI;";

    public async Task<List<Dictionary<string, object?>>> ExecuteMdxQueryAsync(string mdxQuery)
    {
        var result = new List<Dictionary<string, object?>>();
        using var conn = new OleDbConnection(_ssasConnectionString);
        await conn.OpenAsync();

        using var cmd = new OleDbCommand(mdxQuery, conn);
        using var reader = await cmd.ExecuteReaderAsync();

        while (await reader.ReadAsync())
        {
            var row = new Dictionary<string, object?>();
            for (int i = 0; i < reader.FieldCount; i++)
            {
                row[reader.GetName(i)] = reader.IsDBNull(i) ? null : reader.GetValue(i);
            }
            result.Add(row);
        }
        return result;
    }
}

5.2. Endpoint REST API Tiếp Nhận Truy Vấn

Tại SsasController.cs, hệ thống cung cấp endpoint POST /api/v1/ssas/query cho phép truyền trực tiếp câu truy vấn MDX động từ Web Client và nhận kết quả JSON tương thích hoàn toàn với thư viện biểu đồ Chart.js: 

[HttpPost("query")]
public async Task<IActionResult> ExecuteMdx([FromBody] MdxQueryRequest request)
{
    if (string.IsNullOrWhiteSpace(request?.MdxQuery))
        return BadRequest(new { success = false, message = "Truy vấn MDX không được để trống" });

    var result = await _ssasRepo.ExecuteMdxQueryAsync(request.MdxQuery);
    return Ok(new { success = true, source = "SSAS OLAP Cube", data = result });
}
